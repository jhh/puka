# Plan: migrate Blueprint to flake-parts

## Goal and scope

Replace numtide Blueprint with flake-parts while preserving the project's
packages, development shell, formatter, checks and NixOS module exports.

Execute in two stages:

1. Replace the framework and explicitly wire existing outputs.
2. Optionally refactor Nix functions to accept explicit dependencies instead
   of Blueprint-style arguments.

The first stage uses a small compatibility scope, not a Blueprint dependency.
Keep the existing `nix/` layout and package implementations initially.
This document is a migration plan; the migration has not been implemented.

## Constraints

- Run every command inside the Nix devshell, including lint and verification.
- Use Jujutsu for VCS work, not raw Git commands.
- Preserve existing dependency revisions; do not combine the migration with
  package upgrades.
- Preserve both `nixosModules.puka` and `modules.nixos.puka`.
- Preserve package, devshell and passthru-test checks generated by Blueprint.
- Do not add a default package: the current project does not define one.
- Run `jj st` immediately before Nix builds, flake checks and pre-commit so
  the colocated Git tree includes new and edited files.
- Check upstream documentation through Context7 before implementation if
  the relevant inputs or APIs have changed since this plan was written.

## Step 1: inventory existing outputs

Blueprint discovers the following files automatically:

- `nix/lib/default.nix`: top-level `lib`.
- `nix/packages/heroicons.nix`: `packages.<system>.heroicons`.
- `nix/packages/manage.nix`: `packages.<system>.manage`.
- `nix/packages/static.nix`: `packages.<system>.static`.
- `nix/packages/venv.nix`: `packages.<system>.venv`.
- `nix/formatter.nix`: `formatter.<system>` and
  `packages.<system>.formatter`.
- `nix/devshell.nix`: `devShells.<system>.default`.
- `nix/checks/pre-commit.nix`: `checks.<system>.pre-commit`.
- `nix/checks/puka-integration-tests.nix`:
  `checks.<system>.puka-integration-tests`.
- `nix/modules/nixos/puka.nix`: `nixosModules.puka` and
  `modules.nixos.puka`.

Blueprint also creates these checks automatically:

```text
pkgs-heroicons
pkgs-manage
pkgs-static
pkgs-venv
pkgs-formatter
pkgs-venv-ty-check
pkgs-venv-pytest       # Linux only
devshell-default
```

Flake-parts does not automatically reproduce these checks. Importing only
`nix/checks/` would lose package builds, type checking, pytest and the
development-shell build from CI.

The integration test uses `modules.nixos.puka`. External consumers may use
either module export path, so preserve both.

Blueprint also exports framework helpers such as `mkPackagesFor`. No usage
was found in this repository, but inspect downstream flakes before dropping
that helper. Preserve equivalent behavior if consumers require it, or treat
its removal as an explicit API change.

Acceptance: identify all required public outputs and downstream consumers.

## Step 3: replace the Blueprint input and outputs entry point

Remove these declarations from `flake.nix`:

```nix
blueprint.url = "github:numtide/blueprint";
blueprint.inputs.nixpkgs.follows = "nixpkgs";
```

Add:

```nix
flake-parts.url = "github:hercules-ci/flake-parts";
flake-parts.inputs.nixpkgs-lib.follows = "nixpkgs";
```

Keep the existing `nixpkgs`, `treefmt-nix`, `pre-commit-hooks`,
`pyproject-nix`, `uv2nix` and `pyproject-build-systems` inputs unchanged.

Replace the outputs definition with:

```nix
outputs =
  inputs:
  inputs.flake-parts.lib.mkFlake { inherit inputs; } {
    imports = [
      ./nix/flake-module.nix
    ];
  };
```

Acceptance: `flake.nix` delegates explicit output wiring to one module and
does not reference Blueprint.

## Step 4: explicitly wire the existing outputs

Create `nix/flake-module.nix` with the following initial implementation:

```nix
{ inputs, self, ... }:
{
  systems = [
    "aarch64-darwin"
    "aarch64-linux"
    "x86_64-darwin"
    "x86_64-linux"
  ];

  flake = {
    lib = import ./lib {
      inherit inputs;
    };

    nixosModules.puka = import ./modules/nixos/puka.nix {
      flake = self;
    };

    modules.nixos.puka = self.nixosModules.puka;
  };

  perSystem =
    {
      config,
      inputs',
      pkgs,
      system,
      ...
    }:
    let
      # Supply arguments expected by the existing Nix functions.
      call = pkgs.lib.callPackageWith (
        pkgs
        // {
          inherit inputs pkgs system;
          flake = self;

          perSystem = {
            self = config.packages;
            uv2nix = inputs'.uv2nix.packages;
          };
        }
      );
    in
    {
      packages = {
        heroicons = call ./packages/heroicons.nix { };
        manage = call ./packages/manage.nix { };
        static = call ./packages/static.nix { };
        venv = call ./packages/venv.nix { };

        # Preserve Blueprint's formatter package export.
        formatter = call ./formatter.nix { };
      };

      formatter = config.packages.formatter;

      devShells.default = call ./devshell.nix { };

      checks = {
        pre-commit = call ./checks/pre-commit.nix { };

        puka-integration-tests =
          call ./checks/puka-integration-tests.nix { };

        # Preserve automatic package-build checks.
        pkgs-heroicons = config.packages.heroicons;
        pkgs-manage = config.packages.manage;
        pkgs-static = config.packages.static;
        pkgs-venv = config.packages.venv;
        pkgs-formatter = config.packages.formatter;

        # Preserve passthru-test discovery.
        pkgs-venv-ty-check =
          config.packages.venv.passthru.tests.ty-check;

        devshell-default = config.devShells.default;
      }
      // pkgs.lib.optionalAttrs pkgs.stdenv.hostPlatform.isLinux {
        pkgs-venv-pytest =
          config.packages.venv.passthru.tests.pytest;
      };
    };
}
```

The four systems match the standard `nix-systems/default` set used by the
current Blueprint configuration. Confirm this against the baseline.

### Argument and output mapping

- `systems` replaces Blueprint's implicit system discovery.
- `flake` contains outputs that are not indexed by system.
- `perSystem` defines packages, checks, the formatter and the shell.
- `callPackageWith` supplies only arguments each function declares.
- `config.packages` supplies the existing `perSystem.self` package scope.
- `inputs'.uv2nix.packages` supplies the existing
  `perSystem.uv2nix.uv-bin` dependency.
- Existing files retain their relative source paths and implementation.

### Preserve the NixOS module's publisher binding

The NixOS module has an outer function:

```nix
{ flake, ... }:
{
  config,
  lib,
  pkgs,
  ...
}:
```

Blueprint calls that outer function before exporting the module. The import
above preserves this behavior by passing `flake = self`.

Do not merely export the file path: downstream consumers would then need to
provide the `flake` argument themselves.

Acceptance: all existing functions remain unchanged, with explicit output
wiring and the module bound to the publishing flake.

## Step 5: refresh only the flake lock graph

After changing the inputs and adding the module:

```sh
jj st
nix flake lock
jj diff --git flake.nix flake.lock nix/flake-module.nix
```

Confirm that:

- Blueprint is removed and flake-parts is added.
- Blueprint's unused `systems` input disappears if nothing else uses it.
- Existing application dependency revisions remain unchanged.
- Additional lock changes are required dependencies of flake-parts.

Use `nix flake lock`, not a blanket dependency update. No `uv lock`,
`uv sync` or npm update is needed.

Acceptance: the lock graph changes only as required by the framework swap.

## Step 9: optionally remove compatibility arguments

Only start this stage after the framework migration passes verification.
Refactor functions to receive actual dependencies rather than `flake` and
Blueprint's `perSystem` scope.

Suggested dependencies:

- `packages/venv.nix`: `pkgs`, `pythonSet`, `workspace`.
- `packages/static.nix`: `pkgs`, `pythonSet`, `venv`, `heroicons`.
- `packages/manage.nix`: `pkgs`, `venv`.
- `devshell.nix`: `pkgs`, `pythonSet`, `pre-commit`, `heroicons`, `uv`.
- `checks/pre-commit.nix`: `inputs`, `pkgs`, `system`, `pythonSet`.
- `checks/puka-integration-tests.nix`: `pkgs`, `pukaModule`.

For example, change the arguments in `packages/manage.nix` to:

```nix
{ pkgs, venv }:
```

Replace `${perSystem.self.venv}` in the script with `${venv}`. Wire the
package in the flake-parts module as:

```nix
manage = pkgs.callPackage ./packages/manage.nix {
  venv = config.packages.venv;
};
```

Compute shared Python values in the per-system module:

```nix
pythonSet = self.lib.pythonSets pkgs;
workspace = self.lib.workspace;
```

Pass them explicitly to the functions that need them. For the integration
test, pass:

```nix
pukaModule = self.nixosModules.puka;
```

Import `pukaModule` instead of accessing `flake.modules.nixos.puka`.

After all callers are converted, remove the compatibility `call` scope and
repeat output-parity and build verification.

Acceptance: functions expose explicit dependencies without changing output
names or behavior. This stage is optional; stage one already removes the
Blueprint dependency completely.

## Keep separate from this migration

Do not combine the initial framework swap with:

- Adopting treefmt-nix's flake-parts module.
- Adopting the pre-commit flake-parts module.
- Introducing automatic directory imports.
- Adding a default package.
- Changing Python, PostgreSQL or other dependency versions.
- Redesigning the NixOS service module.

These can be follow-up changes after output parity is established.
